2. 찬울님이 만든 것 (쉬운 설명)

기존 Python(FastAPI) 서버 앞에 Java(Spring Boot) 서버를 하나 더 두고, 회원가입·로그인·상담 기록 저장을 맡기는 구조입니다. 사용자의 Gemini 키는 암호화해서 DB에 보관합니다.

구성내용
회원·로그인/api/auth/signup, /login. 비밀번호는 BCrypt로 해시 저장, 로그인하면 24시간짜리 JWT 토큰 발급
Gemini 키 보관/api/users/api-key. 사용자 키를 AES-256-GCM으로 암호화해 DB에 저장(화면에는 다시 보여 주지 않음)
상담 기록/api/history/sessions. 목록·상세·삭제·제목 수정. 본인 세션만 접근 가능
AI 중계/api/ai/sessions/{id}/search, /policies/{id}/ask. 저장된 키를 풀어 FastAPI에 X-Gemini-Api-Key 헤더로 전달하고 질문·답변을 DB에 저장
프론트로그인 창(CommonLoginModal), 사이드바의 "저장된 대화 기록 (Oracle DB)", Vite 길 안내(vite.config.ts)
문서AUTH_AND_HISTORY_PLAN.md(설계), oracle_schema.sql(DB 스키마), function_contracts.md 직접 수정

B. 치명 — 먼저 고쳐야 함

#문제근거조치
B-1치명 대화 저장이 항상 실패DB 제약 CK_MESSAGES_SENDER는 sender_type IN ('USER','ASSISTANT'). 코드는 AiProxyController에서 "user", "assistant"를 저장하고 HistoryService도 변환하지 않음. 질문 저장은 try 밖이라 FastAPI 호출이 끝난 뒤 500 오류가 나고, 답변 저장은 로그만 남기고 사라짐저장 전에 대문자로 변환("USER"/"ASSISTANT"). 상수로 두고 저장·조회·화면 표시 모두 통일. 저장 실패가 AI 응답을 막지 않게 질문 저장도 오류를 삼키고 로그만 남기기
B-2치명 비밀값이 Git에 올라감application.yml에 DB 비밀번호, jwt.secret, security.aes.master-key가 값 그대로 있음. 이미 원격 브랜치에 올라가 있어 이력에도 남음. 마스터 키를 아는 사람은 DB에 저장된 모든 사용자 Gemini 키를 복호화 가능① 세 값을 환경변수로 옮기고(${...}) 파일에서 제거 ② 노출된 값은 모두 교체(DB 비밀번호, JWT 키, AES 마스터 키) ③ AES 마스터 키를 바꾸면 이미 저장된 키 2건을 새 키로 다시 암호화하거나 삭제 후 재등록 ④ 저장소 이력에서 제거 여부 결정(7장 참고)
B-3치명 DB 접속 정보가 개인 로컬용jdbc:oracle:thin:@localhost:1521/XE, 계정 welfareone. 공용 DB는 172.31.57.141:1521/WELFAREONE_ORACLE_DB, 계정 WELFAREONEDB_URL, DB_USERNAME, DB_PASSWORD 환경변수로 받고 기본값은 비워 둠. .env.example에 항목만 안내

C. 주의 — 동작은 하지만 고쳐야 함

#문제근거조치
C-1주의 AI 요청이 Spring을 거치지 않음프론트의 policies.ts는 그대로 /api/policies/search, /ask를 호출하고 Vite가 이를 FastAPI로 바로 보냄. Spring의 /api/ai/sessions/{id}/...는 어디서도 호출되지 않음. 결과: 질문·답변이 Oracle에 저장되지 않고, 서버에 저장한 Gemini 키도 쓰이지 않음(사이드바에는 목록만 보임)로그인 상태에서는 AI 요청을 Spring 경로로 보내도록 프론트 수정. 비로그인은 기존처럼 FastAPI 직행(게스트 모드 유지)
C-2주의 FastAPI 오류 코드가 사라짐FastApiClientService가 4xx/5xx를 모두 일반 예외로 바꿔 INTERNAL_ERROR 500으로 돌려줌. 그래서 프론트가 쓰는 API_KEY_REQUIRED, INVALID_API_KEY, LLM_RATE_LIMITED가 전달되지 않아 키 입력 창과 한도 초과 안내가 동작하지 않음FastAPI의 상태 코드와 error 본문을 그대로 전달(RestClientResponseException을 받아 같은 상태·본문으로 응답)
C-3주의 FastAPI 호출에 시간 제한이 없음RestClient.builder().baseUrl(...)만 있고 연결·응답 제한 없음. AI가 응답하지 않으면 Spring 요청이 무한 대기하고 스레드가 쌓임연결 3초, 응답 60초 정도의 제한(프론트 타임아웃 30초와 맞춰 조정). 초과 시 LLM_RESPONSE_INVALID/INTERNAL_ERROR로 응답
C-4주의 키 저장 방침이 내 쪽 설계와 충돌계약서 제안 8-1은 "서버는 사용자 키를 저장·로깅하지 않고 요청 헤더로만 받는다"인데, 이 설계는 키를 서버 DB에 암호화 저장. 또 내 쪽에 추가한 서버 기본 AI(Qwen)와의 우선순위(저장된 키 → 없으면 서버 AI)를 정해야 함팀 결정 필요: 서버 저장을 허용할지, 허용하면 8장 제안서를 "저장된 키 > 서버 AI > 안내" 순서로 수정
C-5주의 빠진 기능: 지역 목록·정책 상세·설정Spring에는 /regions, /policies/{id}, /config(내가 추가)가 없고 로그인 필수. 지금은 Vite가 FastAPI로 직행해서 동작하지만, 운영에서 Spring 한 곳으로 모으면 401운영 방식 결정(① Vite/Nginx에서 경로별 분기 유지 ② Spring이 나머지를 그대로 중계). ①이 변경이 적음
C-6주의 로그인 토큰 관리JWT를 localStorage에 저장(스크립트 삽입 공격 시 탈취 위험), 서버 쪽 로그아웃·갱신 없음, 유효 24시간. 탈퇴·키 교체 시 기존 토큰이 계속 유효당장은 유지 가능. 보완: 만료 단축+갱신, 또는 HttpOnly 쿠키. 최소한 마크다운 렌더링에 rehype-raw를 쓰지 않는 현재 정책을 유지(스크립트 삽입 방지)
C-7주의 가입 시 계정 존재 노출"이미 가입된 이메일 계정입니다" 메시지로 가입 여부를 알 수 있음. 로그인 시도 횟수 제한도 없음서비스 규모에 따라 허용 가능. 로그인 실패 횟수 제한(예: 5회/10분) 추가 권장
C-8주의 AES 마스터 키 길이 처리키 문자열을 앞 32바이트만 사용하고, 32바이트보다 짧으면 0으로 채움. 키 교체(회전) 절차 없음시작 시 32바이트 미만이면 서버가 뜨지 않게 검증. 교체 절차 문서화
C-9주의 자동 테스트가 없음src/test 폴더에 파일 0개. 위 B-1 같은 문제를 잡을 장치가 없음최소: 메시지 저장(대소문자), 세션 소유자 검증, 오류 코드 전달, 암·복호화 왕복 테스트
C-10주의 빌드 환경·저장소 정리Gradle wrapper가 없어 팀원이 Gradle을 따로 설치해야 함. .gradle/ 캐시와 build/reports 17개 파일이 커밋됨. 프로젝트 문서는 Java 17, 이 PC는 21gradlew를 추가하고 .gradle/, build/를 .gitignore에 넣고 이미 올라간 파일은 제거. JDK 버전 명시
C-11주의 두 개의 상담 기록화면에 브라우저 저장 기록(내가 만든 제목 수정 기능 포함)과 Oracle 기록이 따로 보임. 로그인 시 어느 쪽이 기준인지, 게스트 기록을 계정으로 옮길지 정해지지 않음정책 결정 후 화면 정리(8장 D-2)
C-12주의 내 쪽 기능 일부가 중계에서 빠짐중계가 question, policy_title만 전달해 "자주 묻는 질문" 버튼의 intent(분석 단계 생략·유형별 답변 구성)가 전달되지 않음. 동작은 하되 느리고 형식이 달라짐intent를 그대로 전달하도록 한 줄 추가

8. 결정이 필요한 것

  1. D-1. 사용자 키를 서버에 저장할 것인가 — 저장하면 편리하지만 DB 유출 시 사용자 키가 위험해지고 마스터 키 관리가 필요합니다. 저장하지 않으면 지금처럼 브라우저에만 보관(요청 때마다 헤더 전달)합니다. 서버 기본 AI(Qwen)가 있으면 키 없이도 사용 가능합니다.
  2. D-2. 상담 기록의 기준 — 로그인 사용자는 Oracle 기록만 보일지, 브라우저 기록과 함께 보일지, 게스트 기록을 계정으로 가져올지.
  3. D-3. 서버 구성 — Spring(8080)과 FastAPI(8000)를 모두 띄우는 구조를 운영에서도 유지할지, Python 쪽에 로그인·기록을 합칠지. 이미 Java 코드가 있어 유지가 현실적이지만 두 서버 운영 부담이 생깁니다.
  4. D-4. 공용 DB 위치 — 지금은 팀원 개인 PC입니다. PC가 꺼지면 모든 팀원의 로그인·기록이 멈추므로, 별도 서버로 옮길 시점을 정해야 합니다.

증상원인조치와 재발 방지
FastAPI의 INVALID_API_KEY가 INTERNAL_ERROR로 바뀌어 전달됨Spring 기본 HTTP 클라이언트(HttpURLConnection)는 POST 요청이 401을 받으면 응답 본문을 읽지 못함JDK HTTP 클라이언트로 교체. 모의 서버로는 재현되지 않아 실제 HTTP 서버를 띄우는 테스트(FastApiClientServiceHttpTest) 추가
