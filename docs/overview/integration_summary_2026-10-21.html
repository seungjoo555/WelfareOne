시험 순서 (체크리스트)

  • 게스트 모드: 로그인 없이 지역(서울특별시)·나이 입력 → "월세가 부담돼요" → 후보가 나오고, 후보를 눌러 "신청 방법" 버튼으로 답변을 받는다. 이전과 같아야 합니다.
  • 회원가입: 왼쪽 아래 "로그인 / 회원가입" → 회원가입 탭 → 이메일·닉네임·비밀번호(8자 이상) 입력 → 가입 후 왼쪽 위에 "○○ 님"이 보인다.
  • 기록 저장: 로그인한 상태에서 질문하면 왼쪽 "저장된 대화 기록 (Oracle DB)"에 상담이 자동으로 생기고, 제목이 첫 질문으로 바뀐다.
  • 새로고침 후 복원: 브라우저를 새로고침해도 로그인이 유지되고, 왼쪽 기록을 누르면 이전 대화(질문·후보·답변)가 그대로 나온다.
  • 이어서 질문: 복원한 상담에서 정책을 고르고 "자주 묻는 질문" 버튼을 누르면 같은 상담에 이어서 기록된다.
  • 잘못된 로그인: 틀린 비밀번호로 로그인하면 "이메일 또는 비밀번호가 올바르지 않아요"가 나오고, 같은 이메일로 5번 틀리면 잠시 로그인이 막힌다(10분).
  • 로그아웃: "로그아웃" 후 기록 목록이 사라지고 게스트 모드로 돌아간다.
시험할 때 알아 둘 점
  • Gemini API 키가 없어도 됩니다. 이 서버는 서버에 설정된 키로 AI를 호출하도록 켜 두었습니다(/api/config가 "서버 AI 사용 가능"을 알려 줌). 본인 키를 쓰려면 화면의 "API 키" 버튼에서 입력하면 그 키가 우선 사용됩니다.
  • 검색 DB는 기존 data/chroma(정책 1,418개, 2026-09-21 수집분)를 쓰고 있습니다. 10월 19일에 갱신한 데이터(chroma_update_20261019.zip)는 아직 적용하지 않았습니다.
  • 시험 계정과 상담은 찬울님 PC의 공용 Oracle DB에 실제로 저장됩니다. 시험이 끝나면 만든 계정은 삭제해야 하니 시험한 이메일을 알려 주세요(또는 이메일을 test-이름@example.invalid 형태로 가입하면 구분하기 쉽습니다).
  • 서버는 이 PC에서만 접속됩니다. 다른 PC에서 시험하려면 서버 실행 방법(5장)이 필요합니다.

3. main 대비 추가된 기능

기능쉬운 설명효과
신규 회원가입·로그인이메일·비밀번호로 가입하고 로그인합니다. 비밀번호는 암호화(BCrypt)해서 저장하고, 로그인하면 24시간 쓸 수 있는 출입증(토큰)을 줍니다.사용자별 기록 관리의 기반
신규 상담 기록 저장로그인한 상태에서 한 질문과 AI의 답(후보 정책, 근거, 자료 링크)이 Oracle DB에 자동 저장됩니다. 상담 제목은 첫 질문으로 자동 정해집니다.기기를 바꿔도 이어 볼 수 있음
신규 상담 복원·이어쓰기왼쪽 "저장된 대화 기록"에서 상담을 누르면 대화를 그대로 불러오고, 이어서 질문하면 같은 상담에 기록됩니다.이어 상담 가능
신규 Gemini 키 암호 보관사용자가 원하면 본인 Gemini 키를 서버에 등록해 둘 수 있습니다. 키는 AES-256으로 암호화해 DB에 저장하고 화면에는 다시 보여 주지 않습니다.매번 키를 입력하지 않아도 됨
신규 로그인 보호같은 이메일로 5번 연속 틀리면 10분간 로그인을 막습니다. 남의 상담 기록은 열람·수정·삭제할 수 없고, 남의 상담에 질문을 넣는 시도도 막습니다.비밀번호 무차별 대입·타인 접근 차단
변경 AI 요청 경로로그인한 상태에서는 질문이 "회원·기록 서버 → AI 서버"를 거쳐 가서 기록이 남습니다. 기록 서버에 문제가 생기면 기록만 건너뛰고 검색·답변은 계속 동작합니다.기록 서버 장애가 서비스 중단으로 이어지지 않음
변경 오류 안내키가 없거나 틀렸을 때, AI 호출 한도를 넘었을 때 등의 안내가 로그인 상태에서도 그대로 나옵니다. 로그인 관련 오류(만료, 중복 가입, 잘못된 비밀번호 등) 안내도 추가됐습니다.사용자가 원인을 알 수 있음
변경 키 사용 순서① 요청에 직접 실린 키(화면에서 입력) → ② 서버에 저장된 키 → ③ 없으면 서버 기본 AI.어느 키로 AI가 호출되는지 명확
유지 게스트 모드로그인하지 않으면 지금까지와 똑같이 쓰고, 상담 기록은 이 브라우저에만 저장됩니다.기존 사용자 영향 없음

5. 찬울님 원본 대비 수정한 것 (연결하면서 고친 문제)

찬울님 브랜치를 main에 그대로 붙이면 동작하지 않거나 위험한 부분이 있어 아래를 고쳤습니다. 자세한 점검 내용은 chanul_integration_review_2026-10-19.html에 있습니다.

문제고친 내용
수정 대화 저장이 항상 실패DB는 발신자를 대문자(USER/ASSISTANT)만 허용하는데 코드는 소문자로 저장하고 있었습니다. 대문자로 저장하고 화면에는 소문자로 응답합니다.
수정 남의 상담에 접근 가능다른 사용자의 상담 ID로 AI를 부르거나 기록을 쓸 수 있었습니다. AI 호출 전에 소유자를 확인합니다(남의 것 403, 없는 것 404).
수정 AI 오류 안내가 사라짐키 오류·한도 초과 코드가 모두 "서버 오류"로 바뀌던 것을 그대로 전달하도록 했습니다. 실제 연결에서만 드러난 문제 2건(401 본문 유실, HTTP/2 업그레이드 거절)도 함께 해결했습니다.
수정 AI 서버 무응답 시 무한 대기연결 3초·응답 60초 제한을 걸고, 초과 시 503/504로 안내합니다.
수정 DB 접속 정보가 개인 PC용환경변수(DB_URL, DB_USERNAME, DB_PASSWORD)로 받고 기본 주소를 공용 Oracle로 바꿨습니다.
수정 오류 코드가 계약서와 다름401 UNAUTHORIZED, 403 FORBIDDEN, 401 INVALID_CREDENTIALS, 409 USER_ALREADY_EXISTS, 404 SESSION_NOT_FOUND로 정렬했습니다.
보강 보안·안정성로그인 5회 실패 제한, 기본 임시 계정 자동 생성 끄기, API 키 암호화 마스터 키 길이 검증, 기록 저장 실패가 답변을 막지 않게 처리.
추가 상담 복원찬울님 원본은 상담을 눌러도 지역·나이만 복원됐습니다. 대화 전체를 복원하고 이어쓰기까지 되도록 만들었습니다.
정리 저장소빌드 캐시 17개 파일 제거, gradlew 추가(Gradle을 따로 설치하지 않고 ./gradlew test로 실행).

7. 알려진 한계와 앞으로 할 일

  • 비밀값 교체 보류 — DB 비밀번호, 로그인 토큰 서명 키, API 키 암호화 마스터 키가 저장소 설정 파일에 들어 있습니다. 팀 내부 공유 범위라 지금은 유지하기로 했으며, 외부 공개나 운영 전에 반드시 교체해야 합니다(교체하면 이미 저장된 Gemini 키는 재등록이 필요).
  • 공용 Oracle이 찬울님 개인 PC — PC가 꺼지거나 네트워크가 바뀌면 로그인·기록이 멈춥니다. 검색·AI는 계속 동작하는 구조지만, 운영에는 별도 서버로 옮겨야 합니다.
  • 키 서버 저장 방침 미정 — 서버가 사용자 키를 저장하는 방식이 계약서 제안 8-1("서버는 사용자 키를 저장하지 않는다")과 충돌합니다. 팀 결정이 필요합니다.
  • 상담 기록이 두 곳 — 브라우저 기록과 Oracle 기록이 사이드바에 따로 보이고, 서버 상담을 열면 브라우저 기록에도 사본이 남을 수 있습니다. 기준을 정해야 합니다.
  • 복원한 대화에서는 AI 관련도 판정 결과가 저장되지 않아 "관련도 낮음" 표시가 거리 기준으로 대체됩니다.
  • 로그인 시도 제한은 서버 1대 기준(메모리)이라 서버를 재시작하면 초기화됩니다. 토큰은 브라우저에 저장되며 24시간 후 만료됩니다.
  • 검색 DB 갱신분(2026-10-19 수집)은 아직 서버에 적용하지 않았습니다.
