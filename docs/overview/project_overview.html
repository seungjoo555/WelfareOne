1. 서비스가 하는 일

사용자가 지역·나이와 자연어 질문("월세가 부담돼요", "배고파")을 입력하면 정책 후보를 찾아 보여 주고, 사용자가 고른 정책의 공식 원문에 근거해 질문에 답하는 웹 서비스입니다. 자격 충족을 확정하지 않는 예비 안내이며 최종 확인은 해당 기관에서 합니다.

1
시작 — 시·도, 시·군·구, 나이(선택)를 입력합니다.
2
질문 — 상황이나 정책 이름을 자유롭게 입력합니다(예시 질문 버튼도 있음).
3
후보 확인 — "내 지역 정책"과 "중앙부처 정책"이 따로 나옵니다. 관련 있는 후보가 먼저, 관련도 낮은 후보는 배지와 함께 뒤에 이어지며 3개씩 이전/다음으로 넘겨 봅니다.
4
정책 선택 — 카드를 누르면 "현재 정책"이 되고 자주 묻는 질문 버튼 6개가 나옵니다.
5
후속 질문 — 버튼(지원 대상·지원 내용·신청 방법·신청 기간·필요 서류·문의처)을 누르거나 직접 입력합니다.
6
답변 — 소제목·불릿으로 정리된 답변과 근거 구절, 첨부파일·누리집 링크가 나옵니다. "원문 보기", "다른 정책 찾기", "새 상담"으로 이어갑니다.

6. 질문 분석 (route·intent)

질문이 들어오면 Gemini가 아래 값을 JSON으로 돌려주고, 코드가 허용값·자료형을 검증합니다. 현재 정책이 없는데 "후속 질문"으로 분류되면 코드가 situation_search 또는 specific_policy로 고칩니다. 분석은 seed=0, temperature=0으로 같은 질문에 같은 결과가 나오게 합니다.

route의미 / 이후 처리
situation_search상황을 말하며 추천 요청("월세가 부담돼요"). 엄격한 검색 설정 + AI 재판정 적용
specific_policy특정 정책을 직접 언급. 기본 검색 설정(하한 0.60), 정책명 보너스로 우대, 재판정 안 함
current_policy_question이미 고른 정책에 대한 후속 질문 → 원문 기반 답변
intent (최대 3개)읽는 원문 섹션
eligibility 지원 대상target_criteria
benefit 지원 내용benefit
application 신청 방법application + administrative
administrative 기간·행정administrative + contact_source
required_documents 필요 서류documents + application
contact 문의처contact_source
policy_search / policy_overviewcandidate_summary / overview

분석기는 구어체를 정책 용어로 번역합니다(예: "배고파" → "무료 급식 식사 지원"). 이 번역 결과가 search_query로 검색에 쓰입니다. 읽을 섹션(requested_sections)은 Gemini가 아니라 코드가 intent 표로 정합니다.

7. 검색이 동작하는 순서

1
Gemini 질문 분석 — route, intents, 검색어(구어체 번역), 포함·제외 키워드를 얻음. 429·5xx는 1초, 2초 쉬며 최대 3회 재시도.
2
로컬 질문 임베딩 — 분석기 검색어와 원문 질문(상황형만)을 각각 Qwen3 임베딩으로 벡터화(서버 CPU). 두 검색어를 쓰는 이유: 띄어쓰기·말투에 따라 분석기 검색어가 흔들려도 정답이 사라지지 않게 하기 위함.
3
DB 범위별 조회 — 지자체는 시군구(선택한 시·군·구)와 광역(시·도 전체 정책), 시·군·구가 없으면 시도, 별도로 중앙부처(전국) 범위를 각각 조회(candidate_summary 레코드 대상, 범위당 30개).
4
코드 나이 필터 — 나이를 입력했고 정책의 나이 조건이 명확(age_status=exact)할 때만 최소·최대 나이로 제외. 불명확하면 제외하지 않음.
5
코드 점수 계산 — 점수 = (1 − 거리) + 범위 가산점 + 정책명 보너스 + 키워드 가산 − 제외 감점.
6
코드 거리 하한 — 거리가 하한보다 먼 후보는 제외(계약서 규칙: 관련 없으면 억지로 채우지 않음). 단, 정책명 단어가 질문에 모두 있으면 거리와 무관하게 남김.
7
코드 정렬·분리 — 두 검색어의 결과를 합쳐 정책별로 점수가 높은 후보 하나만 남기고, 지자체/중앙부처를 섞지 않고 각각 점수순 정렬.
7-1
코드 빈 결과 구제 — 상황형 질문이 0건이면 하한을 0.60으로 한 번만 완화해 다시 검색(1위가 0.56처럼 하한을 아슬아슬하게 넘은 경우). 구제된 후보는 "관련도 낮음"으로 가려지며, 무의미 질문은 완화해도 빈 결과.
8
Gemini AI 재판정(상황형 질문, 기본 켜짐) — 범위별 후보 12개를 한 번에 판정(8절). 실패하면 거리순 후보 전체로 대체.
값설정설명
거리 하한기본 0.60 / 상황형 0.55평가 질문 280개 실측: 정답의 99.2% 보존, 무의미 질문 7개 모두 빈 결과. 상황형은 더 엄격(search_profiles.py)
범위 가산점시군구 +0.60 / 광역·시도 +0.35 / 중앙 +0.10상황형 질문은 비율 0(거리 중심 정렬) — 먼 시군구 정책이 가까운 광역 정책보다 위로 가는 문제를 막음

8. AI 관련도 재판정과 후보 표시

왜 필요한가: 거리만으로는 관련 정책과 무관한 정책이 구분되지 않았습니다(상황형 질문 15개 측정: 관련 중앙값 거리 0.45, 무관 0.57로 분포가 겹침). 그래서 검색된 후보를 질문과 함께 Gemini에 보내 "질문한 사람에게 실제로 도움이 되는 정책인가"를 판정합니다.

1
후보 12개(범위별)의 정책명과 요약 300자를 질문과 함께 Gemini 1회 호출(seed=0, 시간 제한 10초).
2
후보별 관련 여부(true/false)를 받아, 판정이 누락·중복되면 실패로 처리. 5xx는 1회만 재시도, 429는 재시도하지 않음.
3
범위별로 관련 판정 후보(점수순) → 무관 판정 후보 순으로 재구성하고, 무관으로 본 정책 ID를 low_relevance_ids로 응답에 담음. 삭제하지 않습니다.
4
판정이 실패하면(한도 초과·시간 초과·형식 오류) 오류 없이 거리순 후보 전체를 돌려주고 relevance_checked=false.

판정 기준: 질문의 상황·필요와 직접 관련이면 관련, 단어만 비슷하면 무관, 지원 대상이 질문자와 명백히 맞지 않으면 무관(예: 질문에 언급이 없는데 장애인·보훈 전용), 지역은 기준 아님, 확실하지 않으면 무관. 질문·정책 문구 안의 지시문은 따르지 않도록 지시합니다.

프론트의 표시 규칙

상황화면 동작
판정 성공(relevance_checked=true)low_relevance_ids에 든 후보가 "관련도 낮음"
판정 안 함·실패거리 0.50 초과 후보를 "관련도 낮음"으로 간주(백엔드 SITUATION_CONFIDENT_DISTANCE와 같은 값)
정책명을 말한 질문(상황형 아님)거리와 상관없이 모두 일반 후보로 표시

9. 후속 질문과 답변 (자주 묻는 질문 버튼)

정책을 고르면 이후 질문은 검색이 아니라 POST /policies/{id}/ask로 갑니다. 두 가지 경로가 있습니다.

경로동작Gemini
버튼 질문요청에 intent(예: eligibility)를 함께 보냄 → 서버가 질문 분석을 건너뛰고 해당 유형의 섹션만 읽어 답변. 항상 같은 섹션을 읽어 결과가 안정적1회(답변)
직접 입력질문 분석 → 현재 정책 질문이면 분석이 정한 intent·섹션으로 답변. 정책과 무관하다고 분류되면 answer=null(화면은 "다른 정책 찾기" 안내), 분류가 애매하면 "확인할 수 없음" 답변(grounded=false)2회(분석+답변)

답변은 이렇게 만들어집니다

1
DB에서 선택 정책의 원문 섹션만 가져옴(overview, target_criteria, benefit, application, documents, contact_source, administrative).
2
질문 유형이 요구하는 섹션만 골라 프롬프트에 넣고, 유형별 [답변 구성] 안내를 함께 전달.
3
Gemini가 원문만 근거로 답변·근거 구절·사용 섹션·grounded를 JSON으로 반환(temperature=0).
4
코드가 검증: 실제 원문에 없는 근거 구절은 버리고, 근거가 없으면 grounded=false. 첨부파일·누리집·법령 링크는 AI가 아니라 코드가 원문에서 추출(다운로드/바로가기 버튼).
질문 유형(버튼)답변 구성(원문에 있는 항목만)
지원 대상누가 대상인가(연령·거주지·소득·재산·취업/학적 상태) → 제외·우선 대상 → 신청 전 확인할 점
지원 내용·금액무엇을 지원하나 → 금액·횟수·기간·한도 → 지급 방식·조건
신청 방법어디서·어떻게 신청 → 절차 순서 → 신청 시기
신청 기간접수 기간 → 사업 기간·마감 → 상시·연중 여부
필요 서류제출 서류 목록 → 서식·첨부파일 → 발급처·유의사항
문의처문의 기관·부서 → 전화·누리집 → 접수 장소
원칙: 원문에 없는 금액·나이·기간·서류를 만들지 않고, 자격을 확정하지 않으며("예비 안내"), 확인되지 않는 항목은 항목마다 반복하지 않고 한 줄로 묶어 "제공된 공식 자료에서는 확인되지 않습니다"라고 안내합니다. 직접 입력한 질문도 분석기가 정한 intent로 같은 구성을 씁니다.

10. API 키(BYOK)·보안·오류 처리

사용자 본인 키(BYOK)

  • 사용자가 화면의 "API 키"에 본인 Gemini 키를 입력합니다. 기본은 탭을 닫으면 사라지는 sessionStorage, "기억하기"를 고르면 localStorage에 저장합니다.
  • 키는 검색·질문 요청의 헤더 X-Gemini-Api-Key로만 전달됩니다(URL·본문·로그에 넣지 않음). 서버는 요청마다 그 키로 Gemini 클라이언트를 만들어 쓰고 저장하지 않습니다.
  • 서버 .env의 키로 대신 처리하는 폴백은 기본 꺼짐입니다(WELFAREONE_ALLOW_SERVER_KEY=true일 때만). 공개 배포에서 운영자 키가 소진되지 않게 하기 위함입니다.
  • 로그에는 오류 종류만 남기고 질문·키·응답 본문은 남기지 않습니다. 실제 키 값은 저장소·.env.example에 넣지 않습니다.

오류 응답과 화면 안내

오류는 항상 {"error": {"code", "message", "details"}} 형식이며, 사용자에게 보이는 한국어 문구는 프론트(constants/text.ts)가 만듭니다.

  • Gemini 429·5xx → 분석·답변은 자동 재시도(1초, 2초 대기, 최대 3회), 그래도 실패하면 위 오류 코드로 안내.

알아 둘 한계

  • 평가 근거가 AI 판정: 관련도 정답을 사람이 아닌 AI가 판정했고 질문도 15개뿐이라 수치는 낙관적일 수 있습니다. 사람 라벨링(질문 50개)으로 기준값을 다시 확정할 예정입니다.
  • 집단 전용 정책: 장애인·보훈 전용 등은 AI 판정이 "관련도 낮음"으로 뒤로 보냅니다. "대상 한정" 표시 방식은 논의가 필요합니다.
  • 원문이 없는 항목: 서류·신청 기간이 DB에 없는 정책은 해당 버튼에서 "확인되지 않습니다"가 나옵니다.
  • 검색 대상이 요약(candidate_summary) 한 건이라 대상·조건 문구가 잘리면 매칭이 약해집니다.
  • 정책 외 질문은 분리된 경로가 없어 "확인할 수 없음" 답변으로 처리됩니다(기존 동작 유지).
  • 모든 AI 단계가 Gemini에 의존해 모델이 바뀌면 결과가 조금 달라질 수 있습니다(seed 고정·폴백으로 완화).

route / intentroute = 질문이 어떤 처리 경로로 가는지(상황 검색 / 정책명 / 후속 질문). intent = 질문의 목적(대상·금액·신청 방법 등)
임베딩 / 거리글을 숫자 벡터로 바꾼 것. 두 글의 거리가 가까울수록(0에 가까울수록) 의미가 비슷함(코사인 거리)
RAG검색(Retrieval)으로 근거 원문을 찾아 그 원문만으로 AI가 답변(Generation)하게 하는 방식
BYOKBring Your Own Key. 사용자가 본인 API 키를 직접 넣어 쓰는 방식
재판정(rerank)검색된 후보를 AI가 다시 보고 관련 여부를 판단해 순서를 바로잡는 단계
grounded답변의 핵심이 제공된 원문으로 뒷받침되는지 여부. false면 화면에 경고
seed / temperatureAI 응답의 무작위성을 줄여 같은 입력에 같은 결과가 나오게 하는 설정
폴백(fallback)한 단계가 실패했을 때 오류 대신 더 단순한 방식으로 대체하는 동작
stateless서버가 사용자 상태를 저장하지 않고 요청마다 필요한 정보(지역·나이·선택 정책)를 받는 구조
MSW / mock백엔드 없이 브라우저에서 가짜 API 응답을 만들어 화면을 개발·검증하는 도구
