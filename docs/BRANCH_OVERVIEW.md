`main`과 비교했을 때 **무엇이 추가됐는지, 어떤 효과가 있는지, 얼마나 안전한지**를 쉬운 말로 정리했습니다. 코드 수준의 자세한 설명과 측정표는 `docs/SEARCH_QUALITY_CHANGES.md`에 있습니다.

> 참고: 사용자 본인 Gemini 키 입력(BYOK), 라이트/다크 테마, 상담 기록 저장은 **이미 `main`에 들어가 있습니다**(PR #3). 이 브랜치의 변경이 아닙니다.

## 세 줄 요약

1. **관련 없는 정책이 덜 나옵니다.** 질문과 먼 정책은 거르고, 애매한 후보는 AI가 한 번 더 확인해 "관련도 낮음"으로 뒤로 보냅니다.
2. **후보를 3개씩 넘겨 볼 수 있고, 자주 묻는 질문은 버튼으로 바로 물어봅니다.** 답변도 질문 유형별로 읽기 쉽게 정리됩니다.
3. **상담 목록의 제목을 직접 고칠 수 있습니다.**

## 1. 이 브랜치가 해결하려는 문제

- "월세가 부담돼요"에 `산후건강관리비용 지원`, `보훈위문금 지급` 같은 **상관없는 정책**이 섞임
- 관련 정책이 없어도 지자체 3개 + 중앙부처 3개를 **억지로 채워서** 보여 줌
- "배고파"처럼 짧은 말은 검색이 안 되고, 같은 질문도 실행마다 검색어가 달라짐
- 처음 3개 밖의 정책은 볼 방법이 없음
- 정책을 선택해도 "궁금한 점을 질문해 보세요" 문구뿐이라 매번 직접 타이핑해야 했고, 답변 형식도 들쭉날쭉함

## 2. main 대비 추가된 기능과 기대효과

| # | 기능 | 쉬운 설명 | 기대효과 |
|---|---|---|---|
| 1 | **거리 하한** | 질문과 너무 먼 정책(거리 0.60 초과)은 결과에서 뺌 | 관련 없는 정책이 억지로 채워지지 않음. 정책과 상관없는 질문("오늘 날씨")은 빈 결과 |
| 2 | **상황형 질문 전용 설정** | 일상 말투 질문은 더 엄격한 기준(0.55)과 "지역보다 내용 우선" 순서로 검색 | 먼 지역 정책이 가까운 정책보다 위로 올라오는 문제 감소 |
| 3 | **키워드 점수 조정** | AI가 뽑은 핵심 단어가 정책명·본문에 있으면 점수를 조금 더 줌(걸러내지는 않음) | 정답을 잃지 않으면서 순위가 조금 좋아짐 |
| 4 | **구어체 → 정책 용어 번역** | "배고파" → `무료 급식 식사 지원`처럼 AI가 정책 검색어로 바꿔 줌 | 짧은 말도 검색됨 |
| 5 | **같은 질문 = 같은 검색어** | AI 분석 결과를 고정(seed) | 실행마다 결과가 달라지지 않음 |
| 6 | **관련도 낮은 후보 구분** | 관련도가 낮아 보이는 정책은 관련 후보 **뒤에 "관련도 낮음" 배지**를 붙여 이어서 보여 줌(관련 후보가 하나도 없으면 눌러서 펼침). 지우지는 않음 | 관련 있는 것이 먼저 보이고, 나머지도 필요하면 확인 가능 |
| 7 | **AI 관련도 재판정** | 검색된 후보를 AI가 한 번 더 "이 질문한 사람에게 도움이 되나?" 확인해서 아니면 뒤로 보냄 | 단어만 비슷한 정책이 앞에서 빠짐. 실패하면 오류 없이 거리순으로 동작 |
| 8 | **후보 3개씩 "이전/다음"** | 후보가 3개보다 많으면 지자체/중앙부처 그룹마다 3개씩 쪽으로 넘겨 봄(관련 판정 → 관련도 낮음 순). 더 없으면 버튼이 안 나옴 | 처음 3개 밖의 정책도 우선순위 순으로 확인. 후보 풀이 12개까지라 판정 지연이 약 0.6초 늘어남 |
| 9 | **상담 제목 직접 수정** | 왼쪽 상담 목록의 ✎ 버튼으로 제목을 고침(Enter 저장, Esc 취소, 비우면 첫 질문으로 복원, 최대 40자) | 여러 상담을 알아보기 쉽게 정리. 고친 제목은 이후 질문을 해도 유지 |
| 10 | **자주 묻는 질문 버튼** | 정책을 선택하면 "지원 대상 / 지원 내용·금액 / 신청 방법 / 신청 기간 / 필요 서류 / 문의처" 버튼이 나옴(선택 안내 메시지와 현재 정책 바). 직접 입력도 그대로 가능 | 매번 타이핑하지 않아도 됨. 버튼 질문은 질문 분석을 건너뛰어 더 빠르고(약 1.4초 단축) 같은 섹션을 읽어 결과가 안정적 |
| 11 | **질문 유형별 답변 구성** | 지원 대상은 "누가 대상 → 제외·우선 대상 → 확인할 점"처럼 유형마다 사람들이 알고 싶어 하는 항목 순서로 소제목+불릿 답변. 원문에 없는 항목은 한 줄로 묶어 안내 | 답변이 들쭉날쭉하지 않고 읽기 쉬워짐(직접 입력한 질문에도 적용) |
| 12 | **검색 안정화** | 같은 의도의 질문은 띄어쓰기·말투가 달라도 같은 결과가 나오게 함: 원문 질문과 분석 검색어를 함께 검색, 후보가 하한 때문에 전부 사라지면 하한을 한 번 완화해 재검색("관련도 낮음" 후보로 표시), 분석기 지침 보강 | "자격증관련 정책 알려줘"처럼 말투가 달라 빈 결과가 나오던 문제 해결. 무의미 질문은 계속 빈 결과, Gemini 호출 횟수 그대로 |

### 사용자가 느끼는 변화

| | 이전 | 이후 |
|---|---|---|
| "월세가 부담돼요" | 산후건강관리비용 등 무관한 정책이 섞임 | 관련 정책이 먼저, 나머지는 "관련도 낮음" 배지로 뒤에 이어짐 |
| "배고파" | 검색 안 됨 | 식사·급식 지원 정책이 검색됨(관련 후보가 없으면 "관련도 낮은 후보 보기" 버튼) |
| 후보가 많을 때 | 3개만 보임 | 3개씩 이전/다음으로 넘겨 봄 |
| 정책 선택 후 | 직접 입력해야 함 | 버튼 한 번으로 질문, 소제목·불릿으로 정리된 답변 |
| 상담 목록 | 첫 질문이 제목으로 고정 | ✎로 제목 수정 |

### 측정으로 확인한 효과

- 상황형 질문 15개에서 첫 화면에 보이는 **무관한 정책 50건 → 21건**(거리 규칙), AI 재판정까지 켜면 보이는 40건이 모두 관련(별도 AI 판정 기준)
- 다른 AI(Claude)로 독립 라벨링해 다시 재도 **관련 정밀도 69% → 97%**(1·2점 관련 기준). 두 AI 판정의 일치도는 kappa 0.76
- 실제 서버로 질문 8개를 돌렸을 때 후보가 3개를 넘어 쪽 넘김이 생기는 질문이 6개(수정 전에는 5개 중 1개)
- 버튼 질문 응답 1.3~2.6초, 직접 입력 약 3.2초(분석 1.4초 + 답변 1.8초)
- 정답 정책 보존: 평가 질문 280개 중 264건(99.2%)이 거리 하한을 넘어도 그대로 남음
- **한계**: 관련 여부 정답을 사람이 아니라 AI가 판정했고 질문도 15개뿐이라 수치는 낙관적일 수 있습니다. 사람 라벨링(`docs/labeling/labeling_guide.pdf`)으로 다시 확정할 예정입니다.

**실패해도 안전하게 동작하는 부분**
- AI 판정이 실패하면(한도 초과, 시간 초과, 형식 오류) 오류 대신 **거리순 후보 전체**로 대체하고 화면은 거리 기준으로 구분합니다.
- 키가 없거나 형식이 틀리면 명확한 오류 코드(401)로 안내하며, 서버는 사용자 키를 저장하거나 로그에 남기지 않습니다.
- 한도(429)에 걸리면 `LLM_RATE_LIMITED`로만 응답합니다. 실측에서 서버 키 하나로 동시에 3건을 보냈을 때 1건이 한도에 걸린 적이 있으며(사용자별 키를 쓰는 운영에서는 해당 없음), 오류 형식은 정상이었습니다.

**알아 둘 한계 (오류는 아니지만 기대와 다를 수 있음)**
- 정책 원문 DB에 서류·신청 기간이 없는 정책은 해당 버튼을 눌러도 "확인되지 않습니다"가 나옵니다. 구성을 바꿔도 없는 내용을 채울 수는 없습니다.
- 정책과 상관없는 질문을 정책 선택 후에 입력하면 "확인할 수 없다"는 답이 나옵니다(`grounded=false`, 기존 동작 유지).
- AI 판정이 엄격해서 장애인·보훈 전용 같은 **특정 집단 전용 정책은 "관련도 낮음"으로 뒤로** 갑니다. "대상 한정" 표시 방식은 팀 논의가 필요합니다.
- 질문 분석·판정·답변 모두 Gemini에 의존하므로 모델 응답이 바뀌면 결과가 조금 달라질 수 있습니다(seed 고정과 폴백으로 완화).

## 4. 아직 하지 않은 것 / 다음 후보

- 사람 라벨링 실행(질문 50개 작성 → 후보 라벨링 → 기준값 확정)
- 특정 집단 전용 정책에 "대상 한정" 표시를 붙일지 결정
- 검색어에 붙는 일반어("지원", "청년") 때문에 같은 정책이 반복되는 문제
- Reranker 모델 병행: 실험 결과 상황형 질문에서는 개선이 확인되지 않아 보류(`feature/jimin-reranker-experiment`)
- 자격 판정, 서류 안내, 신청서 초안, 대화 상태 관리(LangGraph): `docs/DIRECTION_C_PLAN.md`

## 5. 팀원이 확인해 주세요 (합의 필요)

1. AI 재판정을 **기본으로 켤지**(켜면 상황형 검색마다 Gemini 호출 +1회, 약 2.4초)
2. 판정 후보 12개, 한 쪽 3개 숫자
3. 거리 하한 상수 위치(`search_service.py` vs `config.py`): `config.py`는 협의 대상이라 이번에는 옮기지 않음
4. API 변경의 계약서 반영: 검색 응답 필드 2개(`relevance_checked`, `low_relevance_ids`), `/ask`의 선택 필드 `intent`, `generate_answer`의 선택 인자 `intents` → `docs/contract_update_proposal.md` 4-2, 4-3

## 6. 직접 확인하는 방법

```powershell
python -m unittest discover -s tests         # 백엔드 테스트 (키·DB 불필요)
cd frontend; npm test; npm run build         # 프론트 테스트·빌드
```

- **키·서버 없이(mock)**: `cd frontend; npm run dev` 후 질문에 `더보기`(쪽 넘김·관련도 낮음 배지), `관련낮음`, `재판정`을 입력하고, 후보를 선택하면 자주 묻는 질문 버튼이 나옵니다.
- **실제 연동**: 백엔드 `uvicorn app.api:app --port 8000`, 프론트 `.env.local`에 `VITE_USE_MOCK=false`, 화면의 "API 키"에 본인 Gemini 키 입력. 서울특별시 강남구에서 "월세가 부담돼요", "집이 없어요", "배고파"를 입력해 보세요.
