## 1. 이 브랜치가 해결하려는 문제

"월세가 부담돼요", "배고파" 같은 **일상 말투 질문**에서 이런 일이 있었습니다.

- 질문과 상관없는 정책이 결과에 섞임. 예: "월세가 부담돼요"에 `산후건강관리비용 지원`, `보훈위문금 지급`
- 관련 정책이 없어도 지자체 3개 + 중앙부처 3개를 **억지로 채워서** 보여 줌
- "배고파"처럼 짧은 말은 검색이 아예 안 됨
- 같은 질문을 두 번 보내면 검색어가 다르게 만들어짐

## 2. main 대비 추가된 기능과 기대효과

| # | 추가된 기능 | 쉬운 설명 | 기대효과 |
|---|---|---|---|
| 1 | **거리 하한** | 질문과 너무 먼 정책(거리 0.60 초과)은 결과에서 뺌 | 관련 없는 정책이 억지로 채워지지 않음. 아무 상관 없는 질문("오늘 날씨")은 빈 결과 |
| 2 | **상황형 질문 전용 설정** | 일상 말투 질문은 더 엄격한 기준(0.55)과 "지역보다 내용 우선" 순서로 검색 | 먼 지역 정책이 가까운 정책보다 위로 올라오는 문제 감소 |
| 3 | **키워드 점수 조정** | AI가 뽑은 핵심 단어가 정책명·본문에 있으면 점수를 조금 더 줌(걸러내지는 않음) | 정답을 잃지 않으면서 순위가 조금 좋아짐 |
| 4 | **구어체 → 정책 용어 번역** | "배고파" → `무료 급식 식사 지원`처럼 AI가 정책 검색어로 바꿔 줌 | 짧은 말도 검색됨 |
| 5 | **같은 질문 = 같은 검색어** | AI 분석 결과를 고정(seed) | 실행마다 결과가 달라지지 않음 |
| 6 | **관련도 낮은 후보 접기** (화면) | 관련도가 낮아 보이는 정책은 "관련도 낮은 후보 N건 더 보기"로 접음. 지우지는 않음 | 첫 화면에는 관련 있는 것만 보이고, 필요하면 펼쳐서 볼 수 있음 |
| 7 | **AI 관련도 재판정** | 검색된 후보를 AI가 한 번 더 "이 질문한 사람에게 도움이 되나?" 확인해서 아니면 접음 | 단어만 비슷한 정책이 첫 화면에서 빠짐. 실패하면 오류 없이 기존 방식으로 동작 |
| 8 | **후보 3개씩 "이전/다음"** | 관련 있다고 판정된 후보가 3개보다 많으면 지자체/중앙부처 그룹마다 3개씩 쪽으로 넘겨 봄(우선순위 순서 유지). 더 없으면 버튼이 안 나옴 | 처음 3개 밖의 관련 후보도 확인할 수 있음. 판정 비용·지연은 그대로 |
| 9 | **상담 제목 직접 수정** | 왼쪽 상담 목록의 ✎ 버튼으로 제목을 고침(Enter 저장, Esc 취소, 비우면 첫 질문으로 복원) | 여러 상담을 알아보기 쉽게 정리. 고친 제목은 이후 질문을 해도 유지 |

### 사용자가 느끼는 변화

| | 이전 | 이후 |
|---|---|---|
| "월세가 부담돼요" | 산후건강관리비용 등 무관한 정책이 섞임 | 관련 정책 위주, 나머지는 "더 보기" 안에 |
| "배고파" | 검색 안 됨 | 식사·급식 지원 정책이 검색됨 |
| 관련 정책이 없는 질문 | 억지로 6개 채움 | 안내 문구("관련도가 높은 정책을 찾지 못했어요") |

### 측정 결과 (질문 15개, 방향 확인용)

- 첫 화면에 보이는 **무관한 정책: 50건 → 21건**(거리 규칙), AI 재판정까지 켜면 첫 화면 40건이 모두 관련(별도 AI 판정 기준)
- 정답 정책 보존: 평가 질문 280개 중 264건(99.2%)이 하한을 넘어도 그대로 남음
- 비용: 재판정을 켜면 검색 한 번에 Gemini 호출 +1회, 응답 약 2초 늘어남. 끄려면 `WELFAREONE_LLM_RERANK=0`
- **한계**: 관련 여부를 사람이 아니라 AI가 판정했고 질문도 15개뿐이라 수치는 낙관적일 수 있습니다. 그래서 아래 "사람 라벨링"을 준비하고 있습니다.

## 3. 현재 작업 중인 것 (이 브랜치에 push 예정)

위 기능 커밋 2개 위에 아래 내용이 추가로 올라갑니다. 커밋별 설명은 `docs/CLEANUP_COMMITS.md`.

| 작업 | 내용 | 동작 변화 |
|---|---|---|
| 중복 코드 정리 | `.env` 읽기, Gemini 재시도, 검색 흐름이 여러 곳에 복사돼 있던 것을 공용 모듈(`app/env.py`, `app/gemini_retry.py`, `app/search_pipeline.py`)로 정리 | 없음 |
| 테스트 추가 | 위 모듈의 테스트 10개 | 없음 |
| 사람 라벨링 도구 | 평가용 후보 시트 생성 스크립트 + 팀원용 가이드(PDF). 상황형 질문의 정답을 사람이 만들기 위한 준비 | 없음(새 파일) |
| 문서 정리 | README 갱신, 폴더별 안내(docs/, scripts/, data/evaluation/) 추가 | 없음 |

**왜 사람 라벨링을 준비하나**: 지금 수치는 AI가 채점한 것이라 실제보다 좋게 나옵니다. 사람이 만든 정답이 있어야 거리 기준(0.55/0.50), 후보 개수(8개, 3+3)를 믿고 확정할 수 있고, 이후 개선의 효과를 숫자로 비교할 수 있습니다.

## 4. 아직 하지 않은 것 / 다음 후보

- 사람 라벨링 실행(질문 50개 작성 → 후보 라벨링 → 기준값 확정)
- "배고파"에서 `직장인 든든한 점심밥` 같은 **특정 집단 전용 정책**이 접히는 문제: 접지 않고 "대상 한정" 표시를 붙일지 팀 논의 필요
- 검색어에 붙는 일반어("지원", "청년") 때문에 같은 정책이 반복되는 문제
- 자격 판정, 서류 안내, 신청서 초안, 대화 상태 관리(LangGraph): `docs/DIRECTION_C_PLAN.md`

## 5. 팀원이 확인해 주세요 (합의 필요)

1. AI 재판정을 **기본으로 켤지**(켜면 검색마다 Gemini 호출 +1회, 약 2초 지연)
2. 판정 후보 8개, 한 쪽 3개·접힘 3개 숫자
3. 거리 하한 상수 위치(`search_service.py` vs `config.py`): `config.py`는 협의 대상이라 이번에는 옮기지 않음
4. 검색 응답 필드 2개(`relevance_checked`, `low_relevance_ids`)와 새 검색 규칙의 계약서 반영: `docs/contract_update_proposal.md` 참고

## 6. 직접 확인하는 방법

```powershell
python -m unittest discover -s tests         # 백엔드 테스트 (키·DB 불필요)
cd frontend; npm test; npm run build         # 프론트 테스트·빌드
```

화면 확인(서버 실행 후 본인 Gemini 키 입력): 서울특별시 강남구에서 "월세가 부담돼요"와 "배고파"를 입력해 결과를 확인합니다. 키·서버 없이 보려면 프론트 mock 모드에서 질문에 `관련낮음` 또는 `재판정`을 입력하면 접힌 후보 화면을 볼 수 있습니다.
