사람 라벨링 가이드

WelfareOne 청년 복지정책 추천 — 검색 정확도 평가용 정답 만들기  |  2026-10-07  |  작업자 3명 + 프로젝트 담당 지민

1. 이게 무슨 작업인가요?

사용자가 "배고파", "월세가 부담돼요"처럼 말했을 때 시스템이 보여 주는 정책이 정말 도움이 되는지를 사람이 직접 판정하는 작업입니다. 지금까지는 AI(Gemini)가 매긴 점수로만 정확도를 확인했는데, AI끼리 채점하면 실제보다 좋게 나옵니다(AI 두 개의 판정 일치율 81%). 사람이 만든 정답이 있어야 "좋아졌다"를 믿을 수 있습니다.

얻는 것설명
믿을 수 있는 정확도 숫자처음으로 상황형·구어체 질문의 정밀도(보여 준 것 중 맞는 비율)와 재현율(맞는 것 중 보여 준 비율)을 잴 수 있습니다.
기준값 확정지금 잠정값인 검색 거리 0.55/0.50, 후보 8개, 표시 3+3개를 사람 정답 기준으로 가장 좋은 값으로 정합니다.
이후 개선의 효과 확인검색어 개선, 다중 질의 같은 후속 작업을 이 세트로 전후 비교합니다.
AI 판정의 약점 발견특히 장애인·보훈·직장인처럼 특정 집단 전용 정책을 접을지 "대상 한정" 표시로 보여 줄지 결정하는 근거가 됩니다.
논문 평가 자료기존 평가 280개는 "정책 이름 찾기"만 재므로, 상황형 평가가 새로 생깁니다.

2. 전체 흐름과 일정

#단계담당소요(예상)
1질문 작성 (총 50개)팀원 A·B·C각 약 40분
2질문 취합 → 후보 시트 생성(프로그램)Claude약 30분
3후보 라벨링 (본인이 쓰지 않은 질문만)팀원 A·B·C각 약 2시간
4일치도 계산, 의견이 갈린 행 확정Claude + 지민약 1시간
5정확도 측정, 기준값 확정, 결과 문서화Claude당일

마감: 질문 작성 ____월 ____일 / 라벨링 ____월 ____일 (지민이 기입)

배정 규칙
· 자기가 쓴 질문은 직접 라벨링하지 않습니다. 기대하는 답이 정해져 있으면 판정이 한쪽으로 쏠립니다.
· 질문 3개 중 1개는 나머지 한 사람도 추가로 라벨링합니다(일치도 확인용, 전체의 약 1/3). 그래서 라벨링 분량은 1인당 질문 약 22개(행 약 250개) 정도입니다.
· 시트는 프로그램이 사람별로 따로 만들어 드립니다. 본인 이름이 붙은 시트(sheet_본인.csv)만 작업하세요.

4. 작업 1 — 질문 쓰기

양식 파일 situational_questions_template.csv를 복사해 situational_questions_본인이름.csv로 저장하고 채웁니다(엑셀로 열어 CSV UTF-8로 저장).

열쓰는 법
idA01, A02 … (작성자 알파벳 + 번호)
authorA, B, C 중 본인
region_level1 / level2시·도 / 시·군·구. 예: 서울특별시 / 관악구, 세종은 level2 비움. 지역명은 복지로·정책 DB 표기와 같게 씁니다.
age만 나이(숫자). 모르면 비워도 됩니다.
question실제 사용자가 하는 말투 그대로
type구어체 / 상황서술 / 키워드 / 무관질문 / 지역·나이민감
note선택. 특이사항

전체 50개의 구성 (3명 합계)

유형개수예
구어체·감정15"배고파", "춥다", "아기 낳고 몸이 너무 힘들어요"
상황 서술20"월세가 부담돼요", "취업 준비 중인데 구직활동 지원금 받을 수 있나요?"
짧은 키워드8"청년 창업 지원금", "전세 대출 이자"
정책과 무관한 질문4"오늘 날씨 어때", "피자 맛집" → 후보가 안 나오는 것이 정상
지역·나이 민감3특정 지역에만 있을 법한 지원, 나이 제한이 걸리는 지원

각자 위 유형을 골고루 섞어 쓰세요. 무관한 질문은 A 1개, B 1개, C 2개 정도로 나눕니다.

✔ 좋은 질문
  • 정책 이름을 모르는 사람처럼 쓴다
  • 맞춤법이 틀리거나 말이 짧아도 된다
  • 한 질문에 필요 1가지(많아도 3가지)
  • 서울만 쓰지 않고 시·도를 최소 8곳 이상 섞는다
✘ 피할 것
  • 정책 DB나 복지로를 보면서 쓰기(쉬운 질문만 나옴)
  • 같은 의도를 말만 바꿔 3개 이상 쓰기
  • 실제 이름·연락처·주소 등 개인정보
  • "청년 복지 정책 알려줘"처럼 너무 막연한 질문

5. 작업 2 — 후보 라벨링 (가장 중요)

받은 시트(sheet_본인.csv)를 엑셀로 열면 한 줄이 "질문 1개 + 정책 후보 1개"입니다. 아래 두 칸을 채웁니다.

판정 기준: "이 질문을 한 사람이 이 정책을 신청해 볼 가치가 있는가?"

점수의미예 (질문: "월세가 부담돼요")
2 관련질문의 상황·필요에 직접 해당하고, 질문에서 알 수 있는 정보만으로도 대상이 될 수 있음청년월세 지원사업
1 부분주제는 맞지만 대상이 한정되어 질문만으로는 알 수 없거나, 간접적으로만 도움이 됨신혼부부 전월세 대출이자 (신혼부부 한정)
장애인 주거 지원 (장애인 한정)
0 무관주제가 다르거나 단어만 비슷함산후건강관리비용, 보훈위문금
대상한정(✔) 칸특정 집단 전용 정책이면 ✔를 표시합니다(점수와 별개). 장애인, 보훈, 북한이탈주민, 출소자, 농어민, 특정 직업·기업 재직자 등. 이 칸이 "집단 전용 정책을 접을지, 표시를 붙여 보여 줄지" 정하는 근거가 됩니다.

판단이 헷갈리는 경우

상황이렇게 하세요
"배고파" → 직장인 점심 외식 할인 (중소기업 재직자 한정)점수 1 + 대상한정 ✔
"배고파" → 무료법률상담점수 0
"그 지역 정책이라서 관련 있다"는 생각이 들 때지역은 보지 않습니다. 지역 필터는 이미 적용되어 있으니 내용이 질문과 맞는지만 보세요.
요약이 잘려서 대상·내용을 모르겠을 때"원문 링크"를 열어 확인합니다. 링크가 비어 있으면 복지로(bokjiro.go.kr)에서 정책명으로 검색합니다.
그래도 모르겠을 때점수 1 + 메모를 남깁니다. 추측으로 2를 주지 않습니다.
질문 하나에 후보가 하나도 없을 때할 일 없음. 무관한 질문이라면 시스템이 맞게 동작한 것입니다.
무관한 질문(날씨 등)인데 후보가 나왔을 때전부 0
시트에 없지만 알고 있는 더 좋은 정책이 있을 때메모 칸에 정책명을 적어 둡니다(재현율 확인에 쓰입니다).
작업 팁
· 후보의 순서는 일부러 섞여 있고 시스템 점수·거리는 숨겨져 있습니다. 순서에 영향받지 말고 한 줄씩 독립적으로 판단하세요.
· 점수는 숫자 0, 1, 2만 입력합니다. 빈칸이 있으면 제출이 안 됩니다.
· 한 질문의 후보를 한 번에 연속해서 보세요(같은 질문 안에서 기준이 흔들리지 않습니다). 행당 15~30초가 적당합니다.

6. 일치도 확인과 불일치 정리

  • 두 사람이 겹쳐서 라벨링한 약 17개 질문(약 200행)으로 일치도(단순 일치율, Cohen's kappa)를 Claude가 계산합니다. 목표는 kappa 0.6 이상입니다. 미달이면 위 기준 문구를 고치고 그 구간만 다시 라벨링합니다.
  • 두 사람의 점수가 다른 행은 지민이 최종 판정하고 사유를 메모에 한 줄 남깁니다. 같은 유형의 불일치가 반복되면 이 가이드의 "헷갈리는 경우"에 사례로 추가합니다.
  • 측정은 두 방식으로 모두 합니다: ① 2점만 관련으로 인정, ② 1점과 2점을 관련으로 인정. 어느 쪽을 쓸지는 결과를 보고 정합니다.

7. 꼭 지켜 주세요

항목내용
작성자 ≠ 라벨러본인이 쓴 질문의 시트는 받지 않습니다. 받았다면 건너뛰고 알려 주세요.
다른 사람과 의논 금지라벨링이 끝나기 전에는 같은 행의 판정을 서로 묻거나 맞춰 보지 않습니다(일치도 측정이 무의미해집니다). 기준이 애매하면 지민에게만 질문하세요.
개인정보·키질문에 실제 이름·연락처·주소를 쓰지 않습니다. API 키 등은 이 작업에 필요 없습니다.
파일완료한 시트는 이름을 그대로 두고(sheet_본인.csv) 지민에게 전달합니다. 정답 키 파일(labeling_key_PRIVATE.csv)은 라벨러에게 공유하지 않으며 저장소에도 올리지 않습니다.
엑셀 저장"CSV UTF-8(쉼표로 분리)"로 저장해야 한글이 깨지지 않습니다.

8. 제출 전 체크리스트

  • ☐ 질문: 50개 중 내 분량을 모두 썼고 지역·나이가 채워져 있다
  • ☐ 질문: 정책 이름을 보고 쓴 질문이 없다, 개인정보가 없다
  • ☐ 라벨링: 모든 행의 점수가 0/1/2 중 하나다
  • ☐ 라벨링: 특정 집단 전용 정책에 ✔를 표시했다
  • ☐ 라벨링: 확신이 없던 행에는 메모가 있다
  • ☐ CSV UTF-8로 저장했다
