# 검색 관련도 개선 변경 내용 (브랜치 `feature/jimin-search-quality`)

이 문서는 위 브랜치의 커밋 2개(`feat: 상황형 질문 검색 관련도 개선과 LLM 관련도 재판정 (백엔드)`, `feat(frontend): 관련도 낮은 후보 접기와 재판정 결과 반영`)만 다룹니다. 리뷰하는 분이 **무엇이 왜 바뀌었는지, 어떤 값을 정했는지, 어떻게 확인하는지**를 한 번에 볼 수 있게 정리했습니다.

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 해결하려는 문제 | "월세가 부담돼요", "배고파" 같은 **상황형·구어체 질문**에서 관련 없는 정책이 상위에 나오고, 질문과 무관해도 항상 3+3건이 채워짐 |
| 핵심 변경 | ① 검색 **거리 하한** ② 상황형 질문 전용 검색 설정 ③ 분석기 **키워드 점수 조정** ④ 구어체를 정책 용어로 바꾸는 **분석기 지침 + seed 고정** ⑤ 관련도 낮은 후보 **접기**(화면) ⑥ **LLM 관련도 재판정** |
| 효과(질문 15개 측정) | 기본 화면에 보이는 무관한 정책 **50건 → 21건**(거리 규칙), LLM 재판정까지 켜면 기본 화면 40건 모두 관련(별도 판정 기준) |
| 비용 | 재판정을 켜면 검색 한 번에 Gemini 호출 **+1회**, 응답 **약 2초** 지연. 실패해도 오류 없이 거리 기반 결과로 대체. `WELFAREONE_LLM_RERANK=0`으로 끔 |
| 공통 파일 수정 | `app/models.py`, `app/config.py`, `app/main.py`, `docs/function_contracts.md`는 **수정하지 않음** |
| 변경 규모 | 24개 파일, +1,021 / −31 (신규 6개) |

## 2. 문제 (재현 사례)

- 질문과 무관해도 지자체·중앙부처 각각 상위 3개를 억지로 채웠습니다(계약서 9장 규칙 5 "억지로 개수를 채우지 않는다"에 어긋남). "월세가 부담돼요"의 지자체 결과에 `산후건강관리비용 지원`, `보훈위문금 지급`이 섞였습니다.
- "배고파"는 검색어가 그대로 `배고파`라서 어떤 정책과도 멀고(거리 0.71 이상), 하한을 넣으면 0건이 됩니다.
- 시군구 가산점(+0.60)이 거리를 덮어서, 거리가 먼 시군구 정책이 가까운 광역 정책보다 위로 올라왔습니다.
- 같은 질문이 실행마다 다른 검색어로 분석됐습니다(`temperature=0`인데도 "배고파 점심추천"이 3가지로 갈림).
- 거리만으로는 관련/무관이 구분되지 않았습니다. 상황형 질문 15개를 모델로 판정한 결과, 거리 0.60 기준 상위 후보의 정밀도는 지자체 29%, 중앙부처 42%였고 관련 후보와 무관 후보의 거리 분포가 겹쳤습니다(관련 중앙값 0.45, 무관 중앙값 0.57).

## 3. 변경 내용과 정한 값

### 3.1 백엔드

| 항목 | 위치 | 값 | 근거 |
|---|---|---|---|
| 거리 하한 `MAX_DISTANCE` | `app/search_service.py` | **0.60** | 평가 질문 280개: 정답 정책 거리 p95 0.51(최대 0.675), 무의미 질문의 최상위 거리 0.64~0.88. 0.60에서 정답 266건 중 264건(99.2%) 보존, 무의미 질문 7개는 모두 빈 결과 |
| 정책명 일치 예외 `TITLE_EXEMPT_BONUS` | 같은 파일 | **0.5** | 정책명 단어가 질문에 모두 있으면 거리와 무관하게 남김(계약서 9장 규칙 6) |
| 키워드 가산·감점 | 같은 파일 | 정책명 **+0.10**, 본문 **+0.05**, 최대 3개 | 분석기의 include/exclude 키워드로 **점수만 조정**하고 후보는 거르지 않음. 일반어("지원·사업·청년·비용" 등)와 1글자는 무시 |
| 상황형 질문 설정 | `app/search_profiles.py`(신규) | 하한 **0.55**, 지역 가산점 비율 **0.0**(거리순) | `route == "situation_search"`일 때만 적용. 정책명을 말한 질문과 후속 질문은 기존 값 유지 |
| 분석기 지침 | `app/question_analyzer.py` | 구어체 번역 3줄 추가 | "배고파" → `무료 급식 식사 지원`처럼 필요한 지원 분야를 정책 용어로 풀어 씀. 핵심 상황을 버리고 일부 단어만 남기거나 "청년 복지 정책" 같은 일반 검색어로 대체하는 것을 금지 |
| 분석기 seed `ANALYZER_SEED` | 같은 파일 | **0** | 고정 후 질문 3개를 6회씩 보내도 같은 검색어 |
| LLM 관련도 재판정 | `app/relevance_judge.py`(신규) | 후보 범위별 **8개**, 표시 관련 **3개 + 접힘 3개**, 시간 제한 **10초**, seed 0 | 아래 4절 |

- `search_policies()`에는 인자만 추가했고(`max_distance`, `include_keywords`, `exclude_keywords`, `region_bonus_scale`) 기본값은 이전 동작과 같습니다. `max_distance=None`이면 하한이 꺼집니다(평가·튜닝용).
- `api.py`와 `cli.py`는 분석 결과의 키워드와 `search_options(route)`를 검색에 넘기도록 한 줄씩 바뀌었습니다.

### 3.2 프런트엔드

- 상황형 질문의 후보 중 **거리 0.50 초과**(재판정이 켜져 있으면 **무관 판정**된 후보)를 "관련도가 낮은 후보 N건 더 보기"(`<details>`)로 접습니다. 접힌 후보도 선택할 수 있고, 새로고침해도 유지됩니다.
- 정책명을 말한 질문은 거리와 상관없이 모두 보여 줍니다.
- 지자체/중앙부처가 비었을 때 안내 문구를 정리했습니다("관련도가 높은 정책을 찾지 못했어요", "선택한 지역에서는 … 중앙부처 정책을 확인해 보세요").
- 프런트의 `LOW_RELEVANCE_DISTANCE`(0.50)는 백엔드 `SITUATION_CONFIDENT_DISTANCE`와 **같은 값**이어야 합니다(양쪽 주석에 명시).
- mock 모드에서 질문에 `관련낮음`(거리로 접기), `재판정`(LLM 판정으로 접기)을 넣으면 화면을 확인할 수 있습니다.

## 4. LLM 관련도 재판정 동작

```text
질문 ─ 분석기(검색어·키워드·route) ─ 벡터 검색(범위별 후보 8개, 하한 0.55, 거리순)
                                         │  route == situation_search 이고 재판정이 켜진 경우만
                                         ▼
                     Gemini 1회: "질문한 사람에게 실제로 도움이 되는 정책인가?" (후보 전체를 한 번에)
                                         ▼
        범위별로  [관련 판정 최대 3개] + [무관 판정 최대 3개 → 화면에서 접힘]  + low_relevance_ids 응답
```

- 판정 기준: 질문의 상황·필요와 직접 관련이면 관련, 단어만 비슷하면 무관, **지원 대상이 질문자와 명백히 맞지 않으면 무관**(예: 질문에 언급이 없는데 장애인·보훈 전용), 지역은 기준이 아님, 확실하지 않으면 무관.
- 무관 후보는 **삭제하지 않고 접습니다.** 판정이 틀려도 사용자가 펼쳐서 볼 수 있습니다.
- **실패해도 오류가 아닙니다.** 한도 초과(429), 시간 초과(10초), 형식 오류(누락·중복 판정), 5xx 재시도 실패면 후보 풀을 범위별 3개로 줄여 거리 기반 결과를 돌려주고 `relevance_checked=false`로 표시합니다. 429는 재시도하지 않고, 5xx는 1회만 재시도합니다.
- 사용자 키(BYOK)로 만든 분석기의 Gemini 클라이언트를 그대로 재사용해서 키 처리를 따로 하지 않습니다. 로그에는 오류 종류만 남고 질문·키·응답 본문은 남기지 않습니다.
- 프롬프트 안의 지시문(질문·정책 문구에 섞인 명령)은 따르지 않고 판정할 텍스트로만 취급하도록 지시했습니다.

## 5. API 변경 (추가만, 기존 필드는 그대로)

`POST /policies/search` 응답에 필드 2개가 추가됩니다.

| 필드 | 의미 |
|---|---|
| `relevance_checked: bool` | 상황형 질문의 후보를 LLM으로 판정했으면 true, 안 했거나 실패했으면 false |
| `low_relevance_ids: list[str]` | 판정에서 무관으로 본 `policy_id`(응답에 그대로 포함되며 화면에서 접음) |

- 옛 서버·저장된 상담 기록에는 이 필드가 없을 수 있어 프런트는 선택 필드로 처리하고, 없으면 거리 규칙을 씁니다.
- 새 오류 코드는 없습니다. 계약서(`docs/function_contracts.md`) 본문은 수정하지 않았고, 반영 제안은 `docs/contract_update_proposal.md` 4-1, 4-2절에 있습니다.

## 6. 측정 결과와 한계

| 측정 | 방법 | 결과 |
|---|---|---|
| 거리 하한 | 평가 질문 280개(`data/evaluation/`) | 정답 보존 99.2%, 무의미 질문 7개 모두 빈 결과 |
| 키워드 재정렬 | 질문 75개, Gemini 키워드 | 정답 top3 진입 69 → 71, 1위 60 → 63. **키워드 불일치 후보를 제거하는 하드 필터는 정답 5/69(7.2%)를 잃어 채택하지 않음** |
| 구어체 지침 | 평가 질문 47개 회귀 | top3 적중 46 → 46, 1위 46 → 46(손실 없음) |
| 거리 규칙(상황형 설정 + 접기) | 상황형·구어체 질문 15개, 서울 강남구, 후보 판정은 Gemini | 기본 화면 관련/무관 35/50(41%) → 36/21(63%) |
| LLM 재판정 | 같은 15개, 실제 Gemini 호출 | 호출 15/15 성공, 지연 평균 1.8초(최대 2.3초), 기본 화면 40건 모두 관련(별도 판정 기준) |

**한계 (리뷰할 때 감안해 주세요)**
- 관련 여부 라벨을 **사람이 아닌 Gemini가 판정**했고 재판정도 같은 계열 모델이라 정밀도가 낙관적일 수 있습니다. 판정 간 일치율은 81%였습니다. 질문 15개뿐이라 방향을 보는 용도입니다.
- 재판정은 엄격합니다. 관련 정책 60건 중 기본 화면에 올라온 것은 40건(67%)이고 나머지 20건은 접힌 영역에 있습니다. 대부분 특정 집단 전용 정책(장애인·북한이탈주민·출소자·보훈)입니다. 예: "배고파"에서 직장인 전용인 `직장인 든든한 점심밥`이 접혀 기본 화면이 비고 "관련도가 높은 정책을 찾지 못했어요"가 나옵니다.
- 제외 키워드 감점은 분석기가 실제로 내놓은 값이 0건이라 단위 테스트로만 확인했습니다.
- 분석기가 검색어에 "지원", "청년" 같은 일반어를 붙이면 `강남구 교통비 지원사업` 등 같은 정책이 반복해서 끌려오는 문제는 이번에 풀지 않았습니다.

## 8. 확인 방법

```powershell
# 백엔드 단위 테스트 (키·DB 불필요): 89개 통과, 5개 skip
```

수동 확인 (서버 재시작 필요, 화면에서 본인 Gemini 키 입력 또는 `WELFAREONE_ALLOW_SERVER_KEY=true`):
1. 서울특별시 강남구에서 "월세가 부담돼요" → 지자체/중앙부처 결과에 관련 없는 정책이 섞이지 않는지, "관련도가 낮은 후보 N건 더 보기"가 있으면 펼쳐지는지
2. 같은 질문을 경기도 성남시에서 → 지자체가 0건이면 "선택한 지역에서는 관련도가 높은 정책을 찾지 못했어요…" 안내가 나오고 중앙부처는 그대로인지
3. "배고파" → 구어체가 정책 용어로 바뀐 검색어(`이렇게 이해했어요` 줄)로 검색되는지
4. 재판정을 끄고 비교하려면 `WELFAREONE_LLM_RERANK=0`으로 백엔드를 다시 시작
5. mock 모드(프런트만): 질문에 `관련낮음`, `재판정`

거리 하한이 모델·DB 변경 후에도 맞는지는 `python scripts/measure_search_distance.py`로 다시 측정할 수 있습니다.

## 9. 설정과 비용

| 환경변수 | 기본 | 설명 |
|---|---|---|
| `WELFAREONE_LLM_RERANK` | 켜짐 | `0`/`false`/`no`/`off`면 재판정을 끔. 켜면 상황형 질문의 검색마다 Gemini 호출 +1회 |
| `WELFAREONE_ALLOW_SERVER_KEY` | 꺼짐 | (기존) `true`일 때만 서버 `.env` 키로 대신 처리 |

사용자 본인 키(BYOK)를 쓰는 구조라 호출 비용과 한도(429)는 사용자 키마다 다릅니다. 한도에 걸리면 재판정만 건너뛰고 검색은 정상 동작합니다.

## 10. 리뷰·합의가 필요한 점

1. **특정 집단 전용 정책을 어떻게 보일지**: 지금은 질문에 해당 집단 언급이 없으면 접습니다(정밀도 우선). 접지 않고 "대상 한정" 표시를 붙이는 방식은 사용자 프로필을 쓰는 자격 판정 단계와 함께 설계하는 편이 맞아 보입니다.
2. 재판정의 **켜짐 기본값**, 판정 후보 8개와 표시 3+3 숫자: 팀 합의가 필요합니다.
